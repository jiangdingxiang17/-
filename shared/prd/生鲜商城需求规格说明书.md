# 在线生鲜商城系统需求规格说明书

**版本**：V1.0
**日期**：2026-06-30
**状态**：初稿

---

## 1. 项目背景

本项目是一个面向普通消费者和商店管理员的在线生鲜购物 Web 应用系统，作为两周实训周期的实践项目。生鲜电商场景中，消费者需要快速浏览新鲜商品、按品类筛选、管理购物车；管理员则需要掌握库存动态，及时获取低库存预警以安排补货。

由于实训周期有限，系统采用 Flask + SQLite + Bootstrap 技术栈，以单体架构和服务端渲染方式构建，聚焦核心购物流程，确保在有限时间内交付一个可演示、逻辑闭环的完整应用。

---

## 2. 项目目标

1. **功能完整性**：实现用户在线浏览商品、按品类筛选、加购商品、实时查看与修改购物车等核心购物流程。
2. **数据持久化**：所有商品信息、库存数量、购物车记录均存储于 SQLite 数据库，页面刷新后数据不丢失。
3. **智能预警机制**：系统在页面加载及购物车变动时自动检测库存，当任一商品库存低于预设阈值时，在页面顶部醒目位置显示补货通知。
4. **可演示性**：项目可在两周内完成，具备完整的用户交互闭环，适合作为实训成果展示。

## 4. 功能需求

### 4.1 功能概览

| 编号 | 模块 | 功能描述 |
|------|------|---------|
| F001 | 商品浏览 | 以卡片形式展示所有生鲜商品，包含商品名称、图片、单价、当前库存量等关键信息 |
| F002 | 分类筛选 | 提供蔬菜、水果、肉类、鱼类四个品类导航，点击后仅展示对应分类的商品 |
| F003 | 购物车管理 | 支持将商品加入购物车、查看购物车内容、修改商品数量、从购物车移除商品 |
| F004 | 数据持久化 | 商品信息、库存数量、购物车记录全部存储于 SQLite，保证数据在会话间不丢失 |
| F005 | 库存实时追踪 | 页面加载及每次购物车变动时，系统读取最新库存数据并更新页面显示 |
| F006 | 低库存自动预警 | 当任一商品库存量低于预设最低阈值时，在页面顶部显示补货通知横幅 |
| F007 | 管理员查看预警 | 管理员在页面顶部可见低库存预警横幅，提示具体需补货的商品名称及当前库存 |

### 4.2 功能详细说明

#### F001 商品浏览

- **业务逻辑**：系统从商品表中读取全部商品数据，按默认排序（如创建时间或 ID）展示。每张商品卡片显示商品名称、图片、单价、当前库存量。
- **交互逻辑**：用户打开商品列表页，系统渲染商品卡片网格；点击商品卡片可查看详情（可选）或直接触发加购操作。
- **边界与异常**：当商品表为空时，页面展示"暂无商品"提示。

#### F002 分类筛选

- **业务逻辑**：商品表包含分类字段（蔬菜 / 水果 / 肉类 / 鱼类）。用户点击分类导航项后，系统按该分类过滤商品并重新渲染列表。
- **交互逻辑**：点击分类标签 → 页面刷新或局部更新 → 仅展示对应分类商品。当前选中的分类标签高亮显示。
- **规则约束**：分类值为枚举类型，仅支持预设的四类；全部分类（默认状态）展示所有商品。

#### F003 购物车管理

- **业务逻辑**：购物车表记录商品 ID 与加购数量。同一商品多次加购时，数量累加。购物车中商品数量不得超过当前库存量（校验在加购和修改时生效）。
- **交互逻辑**：
  - 加购：点击商品卡片上的"加入购物车"按钮 → 数量 +1 → 购物车侧栏更新。
  - 修改数量：在购物车侧栏中点击 +/- 按钮或输入数量 → 系统校验库存上限 → 更新数据库 → 刷新显示。
  - 移除：点击购物车中商品的删除按钮 → 从购物车表移除该记录 → 刷新显示。
- **边界与异常**：
  - 库存为 0 时，"加入购物车"按钮置灰不可点击。
  - 用户尝试将数量调至超过库存时，系统拒绝并提示"库存不足"。
  - 购物车为空时，侧栏展示"购物车是空的"提示。

#### F004 数据持久化

- **业务逻辑**：所有商品数据、库存数量、购物车记录均持久化存储于 SQLite 数据库。页面刷新或重新打开浏览器后，购物车内容和商品状态保持一致。
- **数据表**：至少包含商品表（products）和购物车表（cart）。

#### F005 库存实时追踪

- **业务逻辑**：每次页面加载以及购物车发生增删改操作时，系统重新查询各商品的最新库存量，并同步更新页面上的库存显示。
- **交互逻辑**：加购商品后，商品卡片上的库存数字即时减少（或保持同步）；页面刷新后库存数据仍准确。

#### F006 低库存自动预警

- **业务逻辑**：系统维护每个商品的最低库存阈值。在页面加载及每次购物车变动后，遍历所有商品，将库存量低于阈值的商品列入预警列表。
- **交互逻辑**：当存在低库存商品时，页面顶部固定位置展示预警横幅，列出商品名称及当前库存。无预警商品时，横幅自动隐藏。
- **规则约束**：阈值在商品表中预设，默认可为 10（可配置）。预警横幅为非阻塞提示，不影响用户正常操作。

#### F007 管理员查看预警

- **业务逻辑**：管理员角色与普通消费者共用同一前端界面，预警横幅对所有用户可见（因系统不包含登录鉴权，以简化实现）。管理员通过页面顶部的预警横幅获知需补货的商品信息。
- **交互逻辑**：管理员打开任意页面时，若存在低库存商品，顶部横幅自动显示补货提醒。

## 5. 非功能需求

| 编号 | 类别 | 描述 |
|------|------|------|
| NF001 | 性能 | 页面加载时间不超过 2 秒；SQLite 查询响应时间不超过 200ms |
| NF002 | 可用性 | 系统支持主流现代浏览器（Chrome、Edge、Firefox）正常访问 |
| NF003 | 数据一致性 | 购物车操作与库存显示之间保持最终一致性，用户操作后页面即时反馈 |
| NF004 | 可维护性 | 代码结构清晰，模块职责单一，便于在两周实训期内完成开发与调试 |
| NF005 | 兼容性 | 系统优先适配桌面端浏览器，移动端适配不在本次范围内 |

## 6. 系统边界

### 6.1 包含范围

- **前端展示层**：商品列表页、分类导航栏、购物车侧栏、库存预警通知栏
- **业务逻辑层**：商品查询、分类过滤、购物车增删改、库存阈值判断与预警消息生成
- **数据存储层**：SQLite 数据库，包含商品表和购物车表
- **管理员功能**：查看预警提示（页面顶部横幅）

### 6.2 不包含范围

- 用户注册 / 登录 / 权限管理
- 在线支付功能
- 库存实际扣减与回滚机制
- 定时任务自动扫描库存
- 预警日志持久化及已读标记
- 移动端适配

## 10. 数据模型（简要）

### 10.1 商品表（products）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 商品唯一标识 |
| name | TEXT | 商品名称 |
| category | TEXT | 分类（蔬菜 / 水果 / 肉类 / 鱼类） |
| price | REAL | 单价 |
| stock | INTEGER | 当前库存量 |
| threshold | INTEGER | 最低库存阈值（预警线） |
| image_url | TEXT | 商品图片路径或 URL |

### 10.2 购物车表（cart）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 记录唯一标识 |
| product_id | INTEGER FK | 关联商品 ID |
| quantity | INTEGER | 加购数量 |
