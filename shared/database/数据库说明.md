## 1. 概述

本数据库为在线生鲜商城系统提供数据持久化能力，存储商品信息、库存数据与购物车记录。数据库使用 SQLite，无需独立数据库服务，数据库文件可随项目一同管理，适合实训项目本地运行与演示。

数据库设计严格遵循需求规格说明书与系统架构设计说明书，遵守以下核心约束：

1. 使用 SQLite 数据库。
2. 至少包含商品表 `products` 与购物车表 `cart_items`。
3. 商品分类包括：蔬菜、水果、肉类、鱼类。
4. 商品表包含库存字段 `stock` 与最低库存阈值字段 `min_stock`。
5. 初始化数据中包含低库存商品，用于演示预警。
6. 加入购物车不扣减库存，不设计库存扣减触发器。

## 3. 表结构说明

### 3.1 商品表 products

存储生鲜商品的基础信息、库存量与低库存阈值。低库存预警判断规则为 `stock < min_stock`。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 商品唯一标识 |
| `name` | TEXT | NOT NULL | 商品名称 |
| `category` | TEXT | NOT NULL，CHECK 取值：蔬菜、水果、肉类、鱼类 | 商品分类 |
| `price` | REAL | NOT NULL，CHECK >= 0 | 商品单价（元） |
| `stock` | INTEGER | NOT NULL DEFAULT 0，CHECK >= 0 | 当前库存量 |
| `min_stock` | INTEGER | NOT NULL DEFAULT 10，CHECK >= 0 | 最低库存阈值（预警线） |
| `image_url` | TEXT | 可为空 | 商品图片路径或 URL |
| `description` | TEXT | 可为空 | 商品描述 |
| `created_at` | TEXT | NOT NULL DEFAULT 当前时间 | 创建时间 |
| `updated_at` | TEXT | NOT NULL DEFAULT 当前时间 | 更新时间 |

**索引**：

- `idx_products_category`：建立在 `category` 字段上，提升分类筛选查询性能。

**约束说明**：

- `category` 通过 CHECK 约束限定为四种合法取值，防止非法分类写入。
- `price`、`stock`、`min_stock` 均约束为非负值，保证数据合理性。
- 低库存预警逻辑由应用层查询实现：`SELECT * FROM products WHERE stock < min_stock;`

### 3.2 购物车表 cart_items

记录购物车中商品与加购数量。由于系统不做登录鉴权，购物车为全局单一购物车，不设计 `user_id` 字段。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 购物车记录唯一标识 |
| `product_id` | INTEGER | NOT NULL，FOREIGN KEY 引用 products(id) | 关联的商品 ID |
| `quantity` | INTEGER | NOT NULL DEFAULT 1，CHECK >= 1 | 加购数量（最小为 1） |
| `created_at` | TEXT | NOT NULL DEFAULT 当前时间 | 创建时间 |
| `updated_at` | TEXT | NOT NULL DEFAULT 当前时间 | 更新时间 |

**约束说明**：

- `UNIQUE(product_id)`：同一商品在购物车中只保留一条记录，重复加购时数量累加。
- `FOREIGN KEY(product_id) REFERENCES products(id) ON DELETE CASCADE`：商品被删除时同步清理对应购物车记录，保证引用完整性。
- `CHECK (quantity >= 1)`：购物车数量至少为 1，数量减至 0 时由应用层删除该记录。
- 库存上限校验（`quantity <= stock`）由应用层在加购与修改数量时执行，不在数据库层以触发器实现，以便返回友好的业务提示信息。

## 4. 核心设计规则

### 4.1 购物车不扣减库存

按照需求与架构设计明确约定，购物车只作为选购清单，加入购物车、修改数量、删除商品等操作只修改 `cart_items` 表，不修改 `products.stock`。因此本数据库**不设计任何库存扣减触发器**。

库存字段 `products.stock` 仅表示商品的当前库存量，不会因购物车操作而变化。库存上限校验由应用层在加购和修改时执行：

```
加购：新数量 = 当前购物车数量 + 加购数量  <=  stock
修改：新数量 <= stock
```

### 4.2 低库存预警机制

低库存预警判断规则：

```sql
SELECT id, name, category, stock, min_stock
FROM products
WHERE stock < min_stock
ORDER BY stock ASC;
```

预警在以下场景触发（由应用层调用）：

1. 首页加载时
2. 分类页加载时
3. 加入购物车后
4. 修改购物车数量后
5. 删除购物车商品后

预警结果与 `cart_items.quantity` 无关，仅由 `products.stock` 与 `products.min_stock` 决定。

### 4.3 分类白名单

`category` 字段通过 CHECK 约束限定取值范围，应用层也应对传入的分类参数做白名单校验，仅允许 `蔬菜`、`水果`、`肉类`、`鱼类` 四种取值。

### 6.2 在 Flask 中初始化（建议方式）

在应用启动时检查数据库状态，若表不存在则自动执行建表与初始化：

```python
import sqlite3

DB_PATH = 'fresh_market.db'
DDL_PATH = 'shared/database/ddl/schema.sql'
DML_PATH = 'shared/database/dml/seed_data.sql'

def init_db():
    conn = sqlite3.connect(DB_PATH)
    cur = conn.cursor()
    with open(DDL_PATH, 'r', encoding='utf-8') as f:
        cur.executescript(f.read())
    cur.execute('SELECT COUNT(*) FROM products')
    if cur.fetchone()[0] == 0:
        with open(DML_PATH, 'r', encoding='utf-8') as f:
            cur.executescript(f.read())
    conn.commit()
    conn.close()
```

## 7. 常用查询示例

### 7.1 查询全部商品

```sql
SELECT id, name, category, price, stock, min_stock, image_url, description
FROM products
ORDER BY id;
```

### 7.2 按分类查询商品

```sql
SELECT id, name, price, stock, image_url
FROM products
WHERE category = '蔬菜'
ORDER BY id;
```

### 7.3 查询低库存预警商品

```sql
SELECT id, name, category, stock, min_stock
FROM products
WHERE stock < min_stock
ORDER BY stock ASC;
```

### 7.4 查询购物车明细（含商品信息）

```sql
SELECT c.id AS cart_id,
       p.id AS product_id,
       p.name AS product_name,
       p.price AS unit_price,
       c.quantity AS quantity,
       (p.price * c.quantity) AS subtotal,
       p.stock AS stock,
       p.image_url AS image_url
FROM cart_items c
JOIN products p ON c.product_id = p.id
ORDER BY c.id;
```

### 7.5 计算购物车总价

```sql
SELECT SUM(p.price * c.quantity) AS total
FROM cart_items c
JOIN products p ON c.product_id = p.id;
```

### 7.6 加入购物车（应用层逻辑示例）

```sql
INSERT INTO cart_items (product_id, quantity)
VALUES (1, 1)
ON CONFLICT(product_id) DO UPDATE SET
    quantity = cart_items.quantity + excluded.quantity,
    updated_at = datetime('now', 'localtime');
```

> 注意：执行加购前，应用层需先校验 `加购后数量 <= products.stock`，否则应返回"库存不足"提示。

## 8. 注意事项

1. **不扣减库存**：购物车的增删改操作只修改 `cart_items` 表，`products.stock` 保持不变。本数据库未设计任何库存扣减触发器。
2. **库存上限校验**：由应用层在加购与修改数量时执行 `quantity <= stock` 校验，便于返回友好的业务提示。
3. **时间字段**：使用 `TEXT` 类型存储本地时间，通过 `datetime('now', 'localtime')` 获取。
4. **外键级联**：`cart_items.product_id` 外键设置 `ON DELETE CASCADE`，商品删除时自动清理对应购物车记录。SQLite 默认不启用外键约束，应用层应在连接后执行 `PRAGMA foreign_keys = ON;`。
5. **重复初始化**：DDL 与 DML 文件均包含 `DROP TABLE IF EXISTS` 与 `DELETE` 语句，可安全重复执行。
6. **编码**：所有 SQL 文件使用 UTF-8 编码，中文字符可正常存储与查询。
